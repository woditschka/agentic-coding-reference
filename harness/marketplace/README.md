# Marketplace packaging source

Producer-side assets for the `marketplace` distribution channel. `harness/package-marketplace.py` renders the canonical `core ∪ stack` runtime into a Claude-plugin marketplace at the repo root: `.claude-plugin/marketplace.json` plus one plugin per (stack, tool) under `plugins/`.

| File | Role |
|------|------|
| `hooks.json` | The Claude plugin's hook wiring — the SendMessage continuation hook, referenced via `${CLAUDE_PLUGIN_ROOT}`. Copied verbatim into each `*-claude` plugin. |
| `setup.sh` | Bundled into every plugin. A consumer runs it once to install the engine sliver into the project — the plugin cache is read-only and skills call engines by project-relative path. Self-locating; gitignores what it installs. |
| `setup-skill.md` | Injected into every plugin as `skills/marketplace-setup/SKILL.md`. The agent-facing one-time setup that runs `setup.sh` — Claude via a `` ```! `` shell block (which expands `${CLAUDE_PLUGIN_ROOT}`), manual for other tools. |

Each plugin also bundles its engine payload under `_engine/` (scripts, schemas, templates), which `setup.sh` copies into the project. The `plugin.json` and `marketplace.json` manifests are generated by the script and stamped with `harness/VERSION`. Three tools read the `.claude-plugin/` format — Claude Code, Copilot CLI, and Junie CLI; OpenCode is not a plugin target. The render is deterministic, and `check-sync.py` guards the committed marketplace against drift. See [the marketplace-channel ADR](../../docs/adr/2026-06-14-marketplace-plugin-channel.md).
