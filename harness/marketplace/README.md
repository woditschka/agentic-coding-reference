# Marketplace packaging source

Producer-side assets for the `marketplace` distribution channel. `harness/package-marketplace.py` renders the canonical `core ∪ stack` runtime into a Claude-plugin marketplace at the repo root: `.claude-plugin/marketplace.json` plus one plugin per (stack, tool) under `plugins/`.

| File | Role |
|------|------|
| `setup.sh` | Bundled into every plugin. A consumer runs it after install and after every plugin update to bring the project-side engine sliver current — the plugin cache is read-only and skills call engines by project-relative path. Self-locating; gitignores what it installs; warns when the declared channel is not `marketplace`. |
| `setup-skill.md` | Injected into every plugin as `skills/marketplace-setup/SKILL.md`. The agent-facing setup/upgrade step: Claude runs `setup.sh` through the Bash tool behind one permission prompt; other tools run it manually. No injected `` ```! `` auto-run and no shipped `allowed-tools` grant — the first aborts on any non-allow check, the second would ship a standing pre-approval. |

Each `*-claude` plugin also carries `hooks/hooks.json` — rendered by `package-marketplace.py` from the settings skeleton (`harness/init/core/.claude/settings.json`): one hook roster, delivered as project `settings.json` on the copy and manifest channels and as the plugin's `hooks.json` on marketplace. Each plugin also bundles its engine payload under `_engine/` (scripts, schemas, templates), which `setup.sh` copies into the project. The `plugin.json` and `marketplace.json` manifests are generated by the script and stamped with `harness/VERSION`. Three tools read the `.claude-plugin/` format — Claude Code, Copilot CLI, and Junie CLI; OpenCode is not a plugin target. The render is deterministic, and `verify-harness.py` guards the committed marketplace against drift. See [the marketplace-channel ADR](../../docs/adr/2026-06-14-marketplace-plugin-channel.md).
