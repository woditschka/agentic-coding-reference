# Glossary

The harness's working vocabulary. Each entry gives the short definition and links the canonical home — the one document that owns the full statement. Terms are alphabetical.

| Term | Definition | Canonical home |
|---|---|---|
| **Agent-team** | The product: the specialist team a consumer installs, runs, and converses with. Leads every consumer-facing surface — front door, adoption guide, walkthrough, marketplace namespace (`agent-team-<stack>`). | [ADR 2026-08-16](adr/2026-08-16-agent-team-names-the-product.md) |
| **Battery** | The deterministic check suite `harness/verify-harness.py`; its header docstring carries the authoritative step list. Tier 0 of the maintainer loop. | [`harness/README.md`](../harness/README.md) |
| **Board** | The reader view of the handoff log: `handoff.py view` renders every slice — header, review-convergence matrix, timeline — to the terminal. The `handoff-board` skill wraps it; the writer side stays in `handoff-append`. | [`handoff-board` skill](../harness/core/.claude/skills/handoff-board/SKILL.md) |
| **Brief** | One of the seven project-owned `docs/` files agents read as authority: four structure-only, three filled defaults. | [`harness-project-api.md` § File Roster](harness-project-api.md#file-roster) |
| **Change grade** | The terminal, advisory verdict — `clear` or `concern` — on how much human attention a passing change deserves before merge. Never routes; nothing auto-merges. | [`change-grading` skill](../harness/core/.claude/skills/change-grading/SKILL.md) |
| **Channel** | How the runtime reaches a consumer: **copy** (committed), **manifest** (gitignored), or **marketplace** (plugin). Detected, never prompted; switching is manual. | [Adoption Guide § Distribution channels](adoption-guide.md#distribution-channels) |
| **Channel doctrine** | The root coordinates, relays, and quotes; it never authors a product, design, or review-contract statement. Four carriers: the paste-ready `prompt_note`, verbatim intake, consultation ownership, and the recorded intake. | [ADR 2026-08-14](adr/2026-08-14-the-root-is-a-channel-not-an-author.md) |
| **Consultation** | A mid-loop roundtrip: a specialist appends a `consultation-request`; the router dispatches the target (`target: "human"` instead halts for the root conversation), then routes the matching response **back to the requester**, never forward. | [`agentic-harness.md` § SDE role](agentic-harness.md#the-system-design-expert-role-in-depth) |
| **Coordinator** | The judgment arm of the two-part router: it classifies untriaged fresh intake and resolves `route`'s `escalate` decisions. It never implements; transitions the table decides never reach it. | [`pipeline-coordinator` agent](../harness/core/.claude/agents/pipeline-coordinator.md) |
| **Core** | The stack-agnostic harness layer (`harness/core/`) every stack shares. Carries no language-specific fact; the battery greps it for stack tokens. | [`harness/README.md`](../harness/README.md) |
| **Doctor** | The deterministic, blocking validator of a project's `docs/` against the harness-project API — stdlib Python, CI-runnable, structure only, never judgment. | [`harness-project-api.md`](harness-project-api.md) |
| **Elicitation pause** | A specialist's mid-dispatch escalation to the human: a `consultation-request` targeting `human` carries the pushback or `foundational` questions; route halts (`human-consultation`) while root converses; the response resumes the requester. | [`agentic-harness.md` § Conversations Stay in Root](agentic-harness.md#conversations-stay-in-root) |
| **Engine** | A deterministic script a skill calls by project-relative path (`handoff.py`, `doctor.py`, `grading.py`). The **engine sliver** — scripts, schemas, templates — is what the marketplace channel installs project-side. | [Adoption Guide § Distribution channels](adoption-guide.md#distribution-channels) |
| **Extension** | A skill, agent, or `scripts/` file the project added under the runtime tree, declared in `[harness] extensions`. Kept and never pruned on upgrade. | [`harness-project-api.md` § Data Files](harness-project-api.md#briefs-feed-agents-data-files-feed-engines) |
| **Extras** | Files `materialize.py` finds under runtime directories that the install did not produce. A retired-paths-manifest match is annotated `[retired]` and removed mechanically; the rest classify per file: declared extension (keep), new extension (keep and record), orphan (remove), or ask. | [`materialize` skill](../.claude/skills/materialize/SKILL.md) |
| **Facet** | One of the change grade's five dimensions, judged categorically and aggregated worst-facet, never average. | [`change-grading` skill](../harness/core/.claude/skills/change-grading/SKILL.md) |
| **Handbook** | A harness-owned method document (`agentic-harness.md` and peers). Ships with the harness, never with a project; the doctor denylists copies in consumer `docs/`. | [`doctor-expectations.toml` `[handbook]`](../harness/core/scripts/doctor-expectations.toml) |
| **Handoff log (ledger)** | The append-only `.scratch/handoff.jsonl` of schema-validated records — the pipeline's working memory and single routing source. | [`agentic-harness.md` § Handoff Contract](agentic-harness.md#handoff-contract) |
| **Harness** | The machinery inside agent-team: the runtime (agents, skills, engines, schemas) and the `/harness` source it materializes from. The standing term in architecture docs, ADRs, and maintainer tooling; agent-team is the consumer-facing register. | [ADR 2026-08-16](adr/2026-08-16-agent-team-names-the-product.md) |
| **Harvest** | The return leg of the loop: pull generalizable improvements from a consumer back into `/harness` — language-agnostic to `core/`, stack-specific to `stacks/<stack>/`. | [Adoption Guide](adoption-guide.md#adopt-in-a-project) |
| **Intake** | Slice intake's one contract with two front doors: the `intake` skill's live discussion under the product expert's contract, or headless seeding from the task prompt. Either exit appends an `intake-decision` record — the owner's request and decisions, quoted verbatim — and `route` dispatches the product expert on it (`intake-ready`). | [`intake` skill](../harness/core/.claude/skills/intake/SKILL.md) |
| **Kernel** | The four disciplines no brief can vary — TDD-first, strategic DDD, spec-driven delivery, the form contract — fixed because the machinery breaks without them. | [`harness-project-api.md` § The Kernel](harness-project-api.md#the-kernel--what-no-brief-can-vary) |
| **Loop** | One of the four concentric feedback cycles: inner (TDD over one behavior), middle (one slice to approval), outer (slice selection), architectural (whole codebase). | [`agentic-harness.md` § Nested Loops](agentic-harness.md#nested-feedback-loops-drive-design-discovery) |
| **Managed chapters** | The harness-owned chapters inside the project-owned `CLAUDE.md`, found by heading and refreshed in place on every upgrade. Everything else in the file stays the project's. | [`harness-project-api.md` § Managed Chapters](harness-project-api.md#the-claudemd-managed-chapters) |
| **Materialize** | Install or upgrade a consumer by completely replacing its harness-owned runtime with the current `/harness`. Onboarding and upgrading are the same operation. | [Adoption Guide](adoption-guide.md#adopt-in-a-project) |
| **Mirror** | A per-tool agent copy (`.github/`, `.opencode/`, `.junie/`) whose body is rendered from the `.claude` base — hand-owned frontmatter, generated body. | [ADR 2026-07-03](adr/2026-07-03-rendered-agent-mirror-bodies.md) |
| **Oracle (semantic)** | An IDE's MCP server (GoLand, IntelliJ IDEA) consulted read-only for semantic ground truth — symbol resolution, inspections, project model. Optional; every workflow degrades to native tools plus the project build. | [Adoption Guide § JetBrains Semantic Oracle](adoption-guide.md#jetbrains-semantic-oracle) |
| **Oracle (task)** | The eval bench's held-out test classes grading one frozen task — never shown to the agent under test. The standard test-oracle sense. | [`evals/README.md` § Oracle contract](../evals/README.md#oracle-contract) |
| **Orphan** | A runtime file an older harness installed that the current one no longer produces. Removed on upgrade — mechanically when the retired-paths manifest covers it, after classification otherwise. | [`materialize` skill](../.claude/skills/materialize/SKILL.md) |
| **Retired-paths manifest** | The cumulative, append-only record (`harness/retired-paths.txt`) of consumer-relative paths the harness once produced and no longer does. Appended mechanically at release, gated both directions by the battery; materialize annotates matches, the marketplace setup prunes them within the engine sliver. | [ADR 2026-08-20](adr/2026-08-20-retired-paths-manifest.md) |
| **Provenance mark** | On a derived brief: how a statement is known — *derived* from the code, *confirmed* by a human with the date, or *not recoverable*. Distinct from the **Stamp**, the harness release date on a scaffolded file's first line. | [`derive-briefs` skill](../harness/core/.claude/skills/derive-briefs/SKILL.md) |
| **Record** | One schema-validated JSONL line in the handoff log, typed by its `type` field (`prd-entry`, `design-block`, `build-pass`, `review-feedback`, …). | [`agentic-harness.md` § Handoff Contract](agentic-harness.md#handoff-contract) |
| **Reference (the)** | This repository: it builds, measures, and distributes agent-team, and carries the docs, eval bench, and decision log. The samples and plugins are its outputs, not the product itself. | [ADR 2026-08-16](adr/2026-08-16-agent-team-names-the-product.md) |
| **Requirement** | One PRD-recorded behavior with a stable `[REQ-XX-NNN]` id. Requirements and slices are different layers: a slice delivers requirements, never redefines them. | [`agentic-harness.md` § Requirements and Slices](agentic-harness.md#requirements-and-slices-are-different-layers) |
| **Retry cycle** | The implementer-attempt window: any fresh `design-block` — original or superseding — resets the 3-retry counter and the grader's `build_retries`. Deliberately wider than the review cycle. | [ADR 2026-08-07](adr/2026-08-07-review-cycle-survives-mid-slice-design-records.md) |
| **Review round** | One review pass — a `build-pass` window. The convergence ladder counts 1 plus earlier passes with substantive roster dissent: critical-only from round 3, human halt past 3 fix rounds. Distinct from the board's display grouping by reviewer reappearance. | [ADR 2026-08-11](adr/2026-08-11-bounded-review-convergence.md) |
| **Review cycle** | The review-history window: it starts at the latest `design-block` carrying a valid `supersedes_record_at`, dissent is cycle-wide, and only a superseding re-triage resets it. | [ADR 2026-08-07](adr/2026-08-07-review-cycle-survives-mid-slice-design-records.md) |
| **Review plan** | A `review-plan` record naming the reviewer roster and read scope for one pass, sized to a logged risk estimate. Emitted by the `build-pass` append, which runs `grading.py review-plan` at gate-pass (`risk` `low`/`high`/`gray`); a `gray` plan defers to the review-planner. Absent, `route` runs the full battery. | [`review-workflow` skill § Risk-Proportional Roster](../harness/core/.claude/skills/review-workflow/SKILL.md) |
| **Review planner** | The judgment agent dispatched only on a `gray` review-plan: it reads the diff and resolves the roster the deterministic engine could not, appending the final `review-plan`. | [ADR](adr/2026-07-09-risk-proportional-review.md) |
| **Reviewer roster** | The mandatory four-reviewer floor — code-quality, test, security, doc — plus any declared `extra_reviewers`. The floor is never subtracted; a review plan narrows which of it a given pass dispatches, and the full roster is the fail-closed default. | [`agentic-harness.md` § Specialist Agents](agentic-harness.md#specialist-agents) |
| **Route** | The deterministic arm of the router: `handoff.py route` executes the Handoff Conditions table and prints `dispatch`, `blocked`, or `escalate`. Fail-closed; never repairs, never guesses. | [`handoff-routing` skill](../harness/core/.claude/skills/handoff-routing/SKILL.md) |
| **Router** | The two-part routing mechanism: `handoff.py route` (the deterministic arm) executes the Handoff Conditions table; the coordinator (the judgment arm) resolves its `escalate` decisions and untriaged fresh intake. | [`agentic-harness.md` § Handoff Contract](agentic-harness.md#handoff-contract) |
| **Runtime** | The harness-owned tree a project receives: skills, agents, hooks, schemas, engines. Replaced wholesale on upgrade; never hand-edited in a consumer. | [Adoption Guide § Contract](adoption-guide.md#the-harnessproject-contract) |
| **Sample** | A materialized consumer committed in this repo (`samples/go`, `samples/java-spring-boot`, `samples/generic`) — each a self-contained project passing its own doctor. | [README § Reference Implementations](../README.md#reference-implementations) |
| **Scope-lock** | Gate 1's check that every changed or removed Non-Goals row in `docs/prd.md` carries a `scope_overrides` entry quoting the owner's decision. The request is never the override; an uncovered change bounces. | [`route-spec.md` § Gate 1](../harness/core/.claude/skills/handoff-routing/route-spec.md#gate-1-product-requirements-expert--system-design-expert-prd-entry) |
| **Scoping Pre-Check** | The pre-dispatch check separating scope from length: more than one behavior bounces back for a re-scope; one long behavior proceeds with a named checkpoint. | [`agentic-harness.md` § Recovery Paths](agentic-harness.md#dispatch-event-contract-and-recovery-paths) |
| **Slice** | The unit of the outer loop: one vertical, independently usable behavior cutting through every layer it touches — one `prd-entry` record. | [`agentic-harness.md` § What a Slice Is](agentic-harness.md#what-a-slice-is) |
| **Stack** | The language-specific harness layer over the shared core: `go`, `java-spring-boot`, or the technology-free `generic` fallback bound through `scripts/stack.sh`. | [`harness/README.md`](../harness/README.md) |
| **Stamp** | The harness release date in `CLAUDE.md`'s first line (`<!-- harness: <date> -->`), landing in every transcript so sessions map to versions. | [ADR 2026-06-27](adr/2026-06-27-harness-version-stamp.md) |
| **Tool surface** | The per-AI-tool agent directories a project installs (`claude` always on; `copilot`, `opencode`, `junie` optional), declared in `[harness] tools`. | [`harness-project-api.md` § Data Files](harness-project-api.md#briefs-feed-agents-data-files-feed-engines) |
| **Triage** | The system-design-expert's per-slice design pass, returning one of six verdicts: `covered`, `minor`, `new`, `foundational`, `conflicting`, `refactor-first`. | [`agentic-harness.md` § SDE role](agentic-harness.md#the-system-design-expert-role-in-depth) |
| **Truncation** | The cause-agnostic abandonment signal: a `dispatch-start` with no subsequent substantive record — cap-hit, mid-stream stop, or network drop alike. Recovery **continues the same slice**; re-split is reserved for the pre-check's over-size branch and non-convergence. The elicitation pause never matches it: its `consultation-request` record shields the dispatch. | [`agentic-harness.md` § Recovery Paths](agentic-harness.md#dispatch-event-contract-and-recovery-paths) |
| **Ubiquitous language** | The project's canonical domain vocabulary (`docs/ubiquitous-language.md`): one term, one meaning, used by every agent, session, and person. Written by the requirements expert as terms resolve. | [`harness-project-api.md` § File Roster](harness-project-api.md#file-roster) |
| **Verdict** | A record's enum decision field: six triage values on `design-block`; `approved`/`changes_requested`/`blocked` on `review-feedback`; `clear`/`concern` on `grader-verdict`. | [`agentic-harness.md` § Handoff Contract](agentic-harness.md#handoff-contract) |
