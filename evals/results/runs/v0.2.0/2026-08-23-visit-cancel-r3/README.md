- ↳ consult **prd-expert** → **human** · Three decisions are needed before I can scope this slice. (1) Do you overturn NG-5, and NG-4 as far as visits are concerned, as an explicit owner decision? A yes narrows both rows and requires a superseding non-goal ADR; the ADR's own convention says narrowing is a recorded owner decision, not an implied one. (2) If yes, does cancelling erase the visit row so it is gone from the pet's record entirely (deletion, NG-4 territory), or does the visit acquire a cancelled state and stop being listed (lifecycle state, which NG-5's rationale explicitly declines to add)? These are different requirements with different acceptance criteria, and the phrase 'removes that visit from the pet's record' does not distinguish them. (3) The problem you state is a visit booked against the wrong pet or the wrong day, which is a correction need. The sample's stated philosophy is forward-only correction. Is cancel-then-rebook the intended shape, or is the real need an amend flow on the existing visit? Two sub-questions follow whichever way (2) goes: 'upcoming visit' is not in docs/ubiquitous-language.md and needs a definition (a visit whose date is later than today?), and if only upcoming visits are cancellable I need to know what happens to a visit whose date has passed while the page was open.
